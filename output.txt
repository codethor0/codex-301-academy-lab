## Resources and Guides handoff

The Resources and Guides pages already follow the shared informational-page
layout and appear in the existing navigation. The reusable add-new-page skill
captures the established workflow for adding similar static pages.

The documentation-platform team owns the approved AGENTS.md articles, stable
identifiers, categories, destinations, and written sections. The web experience
team owns the catalog, article pages, category filters, accessibility, and
navigation.

Preserve the approved article content, existing Guides content, Resources page,
shared navigation, and protected routes when extending the application. The
article-validation module, Guides catalog, article pages, category filtering,
reusable frontend reviewer, and additional acceptance checks have not been
implemented.

### Browser smoke checks

Brave showed six cards in the unfiltered view and two for each approved filter.
A direct Best Practices URL loaded with the correct selection. Getting Started
and All guides updated the URL and list. Tab reached Workflows and an article
link, Enter activated both, and the filter retained visible keyboard focus.
Back restored the filtered list and Forward reopened the article. The article
showed the approved heading and all three sections. The primary navigation
opened Resources with its Docs, Examples, and FAQ links. All six article routes
were verified by the automated response checks.

### Independent review

The pre-implementation frontend reviewer and temporary content investigator ran
as separate children of a CLI session using the enforced read-only sandbox and
approval policy `never`. Their findings confirmed the approved six-route mapping,
the editorial boundary, and the need for focused tests of navigation and URL
behavior. The starter's CLI skipped project-local discovery, so the named role
was registered for those invocations with the project TOML as its role file.
The CLI confirmed `frontend_reviewer` and used the same role for one bounded
read-only release review.

The final reviewer found that category changes lacked an announcement and that
primary navigation was only asserted on a single filtered page. The fixes add a
persistent polite results status and check the primary links and current page on
each protected route. The final check results above include both fixes.
